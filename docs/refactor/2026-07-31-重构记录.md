# 2026-07-31 重构记录

## 背景

根据《skill-review-20260731》审查暴露的 4 个问题，对 `read_documents` 与 `template-write` 两个 skill 进行系统性重构，并在真实任务（实习总结报告 .doc 第三部分填写）中迭代验证。

## 一、审查问题修复

### 1.1 `.doc` 写入场景覆盖空白

`template-write` 新增 `.doc` 转换适配层（`doc_convert.py`）：

- CLI 入口检测 `.doc` 模板 → Word COM 转换为临时 `.docx` 工作副本 → 复用既有 .docx 全流程
- 原始 `.doc` 只读打开、永不被修改（满足「先复制再填写」原则）
- 输出默认 `.docx`；用户显式命名 `.doc` 输出时，填写完成后经 Word COM 回转旧格式

### 1.2 临时文件管理

`mktemp_in_dir`（在源文档目录创建 temp/）改为系统临时目录 + 自动清理：

- `read_documents`：COM 中间产物走系统 temp，`try/finally` 保证清理
- 清理增加重试（`rmtree_retry`），应对 Windows 索引器/杀软的瞬时文件锁

## 二、pywin32 重构（弃 PowerShell）

两个 skill 的全部 COM 调用从 ps1 脚本改为 pywin32 进程内直调，删除所有 ps1 文件：

- `template-write`：删 `ps1/convert_doc.ps1`
- `read_documents`：删 `ps1_scripts/`（3 个提取脚本）
- 附带收益：修复旧 COM 遍历在合并单元格上的崩溃（「成员不存在」错误）

## 三、format-markdown frontmatter 保护

`gen_md.py` 新增 `_split_frontmatter()`：YAML 元数据块（开头的 `--- ... ---`）原样保留，不参与任何格式化规则。修复块间距规则把 YAML 列表项当 Markdown 内容、插入空行破坏结构的问题。

## 四、SKILL 功能增强

### 4.1 scan 报告表格

`--scan` 新增 Tables 段：idx、是否有内容、文本预览、**单元格内空段数**。空段数是「表内占位答案区」的判据（如签名表单元格内含 27-41 个空段的中文表单）。

### 4.2 replace 安全护栏

无样式边界（`end=None`）且标题后仍有元素时，replace 模式拒绝执行并提示改用 `--section-mode append` 或 `--heading-style`，防止误删后续章节。

### 4.3 决策表与信息完整性声明

SKILL.md 新增「scan 输出解读决策表」：0 标题 → append、表内空段 → cell、空表格 → 核对 body 顺序等。并声明结构信息只需 `--scan` + `extract_files` 两个命令，明令禁止内联 python-docx 探测脚本。

### 4.4 标题匹配语义修正

文档修正为与源码一致：**子串匹配、大小写不敏感、仅查 body 直接段落**（表格单元格内文本不算标题）。

### 4.5 Shell 兼容示例

命令示例去掉 `&&`/`$(pwd)` bash 专属语法，改为 shell 无关写法（workdir + 绝对路径），适配 Windows PowerShell 5.1。

### 4.6 互引 Location 提示

两个 SKILL.md 互引处注明「同目录」位置（`X/../template-write/`），避免会话只找到 `.claude` 旧副本。

## 五、边界转换架构（read_documents）

```txt
.doc/.ppt/.xls ──COM SaveAs──> .docx/.pptx/.xlsx ──python-docx/python-pptx/openpyxl 提取
```

- 新增 `convert.py`（通用转换层）与 `conv_worker.py`（子进程入口）
- 三个提取器改为「转换优先」，删除约 150 行手写 COM 文档遍历
- 老格式获得资源提取能力（`word/media/` + `word/embeddings/`）
- 实测验证：69 张图片往返 md5 全同；嵌入 xlsx 对象完整存活（唯一损失：宏）

## 六、Word 锁死问题根治

pywin32 进程内 COM 无超时机制，Word 卡死会永久阻塞主流程。修复：

- COM 调用隔离到子进程（`conv_worker.py`），父进程 `subprocess.run(timeout=120)` 带超时等待
- 超时后杀子进程 + `taskkill` 清理无响应 Office 僵尸
- 两个 skill 同步实施；最坏情况 120 秒后报「转换超时」，主流程不再被阻塞

## 七、表内占位答案区支持（cell 模式）

中文表单常见形态：标题后紧跟表格，单元格内含 N 个空占位段落 + 签名行。新增：

- **scan 标注**：`单元格内空段: N`
- **`--section-mode cell`**：定位标题 → 找首个含空段的单元格 → 删除占位空段 → 在终止段（签名行）前插入内容
- 单元格终止段保留以满足 `w:tc` 架构约束；验证计数改为递归遍历（body 级与单元格内标记统一支持）
