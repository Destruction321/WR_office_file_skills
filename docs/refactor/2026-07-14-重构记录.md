## bookmark 内存验证替代文本匹配指针

原来的 `_verify_filled` 重新打开文件，逐段遍历匹配标题文本指针，依赖 `all_child_texts`（文档全量文本）和 `heading_keys`（标题列表），体量大且脆弱。

替代方案（变体 3）：插入时给每节首末段包裹 `bookmarkStart`/`bookmarkEnd`，验证时按 bookmark 数段内 `<w:p>`，完了清标记再 save。零文本匹配，零重开文件。

**改动文件：**

- `elements.py`：
  - 新增 `mark_section_start` / `clear_section_marks` / `count_paras_in_section`
  - `insert_items` 返回 `(para_count, img_count, first_p, last_p)`，调用方自行打标记
- `section_filler.py`：
  - `_verify_filled` 完全重写：`(doc, filled_summary)`，内存验证，bookmark 定位
  - save 顺序：验证 → `clear_section_marks` → `doc.save`（落盘零 bookmark 残留）
  - `filled_summary` 加 `sec_id` 第四项

**修 bug：**

- `count_paras_in_section` 原用 `body.iter()` 深度遍历 → 误数表格内嵌 `<w:p>` → 改用 `for el in body`（直接子级）
- `mark_section_start` 用 `w:id="0"` → 与文档已有 bookmark 冲突 → 改用高基数 `9{idx:04d}`

**验证：** 端到端通过，落盘 `sec:` bookmark 残留 = 0。

## `elements.py` 自管 docx 依赖

此前 `elements.py` 宣称"零 docx 依赖"，但实际操作 docx 对象（Document、CT_P）、接收 `Inches`——约束名存实亡。`qn`/`OxmlElement`/`Inches` 从调用方传入导致参数膨胀（`insert_items` 7 参、`mark_section_start` 5 参）和 `_FillSession` 胶水方法。

**方案：** `elements.py` 模块级 `ensure_import` 自管三者，消除参数传递 + `_FillSession` 胶水方法。

**参数变化：**

| 函数                     | 改前  | 改后                                     |
| ------------------------ | ----- | ---------------------------------------- |
| `insert_items`           | 7 → 4 | **3**（`doc, anchor, items`）            |
| `mark_section_start`     | 5     | **3**（`first_para, last_para, sec_id`） |
| `clear_section_marks`    | 2     | **1**（`body`）                          |
| `count_paras_in_section` | 3     | **2**（`body, sec_id`）                  |
| `_build_image_para`      | 3     | **2**（`doc, item`）                     |

`_FillSession` 从 5 字段 + 2 方法 → **3 字段**（`body, doc, locate_ctx`），`Inches`/`OxmlElement` 字段 + `mark_section`/`clear_marks` 方法全部删除。
