# 2026-07-15 重构记录

## PDF 库评估：确认 PyMuPDF 为最佳选择

以 `test/信息安全.pdf`（17 页，含复杂表格 + 流程图）为基准，对比 PyMuPDF、pdfplumber、pymupdf-layout：

| 维度 | PyMuPDF | pdfplumber | pymupdf-layout |
| --- | --- | --- | --- |
| 表格提取 | 正确 | 合并单元格表头顺序混乱 | AI 模型，更准 |
| 多栏阅读顺序 | 正确 | **完全打乱**（"信息安全"→"全安息信"） | AI 模型，更准 |
| 图片提取 | 内置 | 不支持 | 不直接支持 |
| 依赖体积 | ~20MB | ~5MB | 41.6MB wheel + 200MB ONNX 模型 |
| 许可证 | AGPL | MIT | Polyform Noncommercial |
| 代码改动 | 零（已是当前方案） | 需重写 | 需重写 + 换 `pymupdf4llm.to_markdown()` 管道 |

**结论：保留 PyMuPDF。** pdfplumber 在复杂布局上阅读顺序严重错误；pymupdf-layout 需管道级重写 + 非商用许可，对当前 skill 过重。

## `sort=True`：启用 PyMuPDF 内部排版分析

`page.get_text("blocks")` → `page.get_text("blocks", sort=True)`。

默认按 PDF 内部存储顺序返回文字块（创建顺序），`sort=True` 启用排版分析引擎按人类阅读顺序重排（从上到下、从左到右，区分多栏布局）。

## 动态阈值段落合并

### 改动

原硬编码阈值 `abs(x0 - px0) < 30 and 0 < gap < 12` 无法适应不同字号。

改为基于字号的动态计算：

- `get_text("blocks")` → `get_text("dict", sort=True)`，从 span 级别取字号 `span["size"]`
- 每个文字块记录 `font_h`（块内最大字号）
- 合并阈值：缩进容差 `ref_h * 2.5`（容纳首行缩进 2 字符），行间距 `ref_h * 1.5`
- `ref_h = max(font_h, pfont_h)`——取相邻两块字号较大者

### 关键 bug 修复

初版用 `ref_h = max(font_h, py1 - py0)`（合并后块高），导致合并后块高膨胀 → 阈值雪崩 → 整页段落被粘成一块。

修正为用**字号**（`pfont_h`）而非块高，合并后阈值不随块增大。

### 效果

| 指标 | 硬编码（改前） | 动态阈值（改后） |
| --- | --- | --- |
| 输出行数 | 799 | 550 |
| 段落合并 | 同段多行有时未合并 | 正确合并 |
| 不同段落 | 正确分隔 | 正确分隔 |

## 复杂排版页自动渲染为图片（两层兜底）

### 背景

流程图、图示等复杂排版页文字提取结果碎片化严重（如第 11 页：20 个块，大量 1-2 字碎片"毕""业""设""计"）。

### 第一层：代码启发式自动检测

`_is_complex_layout(n_blocks, short_ratio, n_tables, x_ratio)`：

- `n_tables > 0` → 排除（保住表格结构化数据）
- `n_blocks > 10 and short_ratio >= 0.4 and x_ratio > 0.5` → 触发渲染

三个条件缺一不可：

| 条件 | 作用 |
| --- | --- |
| `n_blocks > 10` | 块数多 = 碎片化 |
| `short_ratio >= 0.4` | 40%+ 块文字 <5 字 = 标签碎片 |
| `x_ratio > 0.5` | 文字横向散布 >50% 页宽 = 流程图（排除目录页窄列） |

`x_ratio` 条件用于排除目录/索引页误判：目录页短块多但集中在窄列内（x_ratio 低），流程图文字散布整页（x_ratio 高）。

### 第二层：AI 按需渲染

每页末尾输出 `[meta]` 元数据，AI 判断后可用 `--render-page N` 强制渲染指定页：

```bash
python -m extract_files --paths-file ... --assets-dir ... --render-page 7 14
```

`--render-page` 覆盖所有检测条件（包括表格排除），需配合 `--assets-dir`。

### 元数据格式

```txt
[meta] blocks=N avg_len=M short=K tables=T x_spread=PP%
```

### 测试结果

| 页面 | meta | 行为 |
| --- | --- | --- |
| 第 11 页（流程图） | `blocks=20 avg_len=12 short=8 tables=0 x_spread=118%` | 自动渲染 ✓ |
| 表格页（3-8, 12-17） | `tables>0` | 正常 markdown ✓ |
| 文字页（1-2, 10） | `x_spread=33-34%` | 正常文字 ✓ |
| 签字页（9） | `blocks=4 short=1` | 正常文字 ✓ |

零误报，零漏判。

## `_extract_page` 拆分

原函数 ~130 行 8 步骤，拆出 3 个独立函数：

| 函数 | 职责 | 行数 |
| --- | --- | --- |
| `_collect_text_blocks(page, table_bboxes)` | dict 解析 + 过滤表格区域 + 取字号 | ~20 |
| `_merge_text_blocks(text_blocks)` | 动态阈值段落合并算法 | ~15 |
| `_render_items(items)` | text + table → markdown 输出 | ~25 |

`_extract_page` 缩至 ~55 行，变为纯编排：检测表格 → 收集文字 → 合并 → 算元数据 → 判断渲染 → 收集排序 → 渲染输出。
